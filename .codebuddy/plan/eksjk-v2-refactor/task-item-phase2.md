# 实施计划 — 阶段二：认证与基础管理

> **对应需求**：需求 4（认证与权限）、需求 5（用户管理）、需求 6（机构管理）、需求 7（PC 端布局与交互）
> **目标**：实现用户认证授权体系、用户管理、医疗机构管理、PC 端页面框架等基础管理功能，为后续业务模块提供完整的权限和元数据支撑。
> **前置依赖**：阶段一全部完成

---

- [ ] 1. 实现后端用户 Entity 与认证登录 API
   - 在 `eksjk-model` 中创建 `User` Entity（兼容 V1 表结构），包含基本信息、职业信息、角色信息、状态信息、微信绑定、审计字段
   - 在 `eksjk-mapper` 中创建 `UserMapper`（继承 `BaseMapper<User>`）
   - 在 `eksjk-service` 中实现 `AuthService`：登录验证（BCrypt 密码校验）、Sa-Token 生成 Token（JWT 模式，携带角色和 hospital_id）、登出、Token 刷新
   - 在 `eksjk-web` 中实现 `AuthController`：`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/info`
   - 实现登录日志记录（IP、时间、用户角色、所属医院）
   - 实现密码策略：首次登录强制改密标记、超过 6 个月提醒改密标记、密码复杂度校验（6-30 位，数字+字母）
   - 实现 Hashids 编码用户 ID（对外暴露时自动编码/解码）
   - _需求：4.2、5.1_

- [ ] 2. 实现后端角色权限控制与数据范围过滤
   - 实现 Sa-Token 权限拦截器配置：路由拦截规则（公开接口 vs 需认证接口）
   - 实现四级角色权限注解校验（`@SaCheckRole`）
   - 实现数据范围过滤 AOP 切面：根据当前用户角色自动注入查询条件
     - 超级管理员：不过滤（全局数据）
     - 医院管理员：自动追加 `hospital_id = 当前用户所属医院`
     - 普通医生：自动追加 `creator_id = 当前用户 ID`
   - 实现 CORS 跨域配置（开发环境允许 localhost，生产环境白名单）
   - _需求：4.3、14.6_

- [ ] 3. 实现后端医疗机构管理 API
   - 在 `eksjk-model` 中创建 `Unit` Entity（兼容 V1 表结构），包含基本信息、联系信息、扩展信息、状态信息、审计字段
   - 在 `eksjk-mapper` 中创建 `UnitMapper`
   - 在 `eksjk-service` 中实现 `UnitService`：机构 CRUD、状态管理（禁用机构联动禁用用户）、唯一性校验、关联统计查询
   - 在 `eksjk-web` 中实现 `UnitController`：
     - `GET /api/units`（分页列表，支持多条件筛选）
     - `GET /api/units/{id}`（详情，含关联统计）
     - `POST /api/units`（新增）
     - `PUT /api/units/{id}`（编辑）
     - `PUT /api/units/{id}/status`（启用/禁用）
     - `DELETE /api/units/{id}`（删除，有关联数据时拒绝）
     - `GET /api/units/options`（轻量级选项列表，供下拉选择）
   - 所有接口限定 `@SaCheckRole("super_admin")`，选项列表接口除外
   - _需求：6.1、6.2、6.3、6.4、6.5_

- [ ] 4. 实现后端用户管理 API
   - 在 `eksjk-service` 中实现 `UserService`：用户 CRUD、分级查询（超级管理员全局/医院管理员本院）、状态管理、密码重置
   - 在 `eksjk-web` 中实现 `UserController`：
     - `GET /api/users`（分页列表，根据角色自动过滤数据范围）
     - `GET /api/users/{id}`（详情）
     - `POST /api/users`（新增，医院管理员只能创建本院普通医生）
     - `PUT /api/users/{id}`（编辑，医院管理员不可修改角色和所属医院）
     - `PUT /api/users/{id}/status`（启用/禁用，立即失效 Token）
     - `PUT /api/users/{id}/reset-password`（重置密码）
     - `DELETE /api/users/{id}`（逻辑删除）
   - 实现个人中心 API：`GET /api/users/profile`、`PUT /api/users/profile`、`PUT /api/users/password`
   - 权限校验：超级管理员和医院管理员可访问用户管理，普通医生返回 403
   - _需求：5.2、5.3、5.4、5.5_

- [ ] 5. 实现 PC 端主布局框架
   - 在 `src/layouts/` 下创建 `MainLayout.vue`：经典三栏布局（左侧边栏 + 顶部栏 + 主内容区）
   - 实现左侧边栏组件 `SideBar.vue`：
     - 系统 Logo + 系统名称
     - 可折叠菜单树（宽度 210px ↔ 64px，平滑动画过渡）
     - 当前选中菜单高亮，自动展开父级菜单
   - 实现顶部栏组件 `TopBar.vue`：
     - 侧边栏折叠按钮
     - 面包屑导航（根据路由自动生成）
     - 右侧用户信息区（头像、用户名、下拉菜单：个人中心/修改密码/退出登录）
   - 实现页面切换过渡动画（fade 效果）
   - 配置嵌套路由：`MainLayout` 作为父路由，子路由渲染在主内容区
   - _需求：7.1、7.3_

- [ ] 6. 实现 PC 端动态菜单与权限路由
   - 在 `src/stores/` 下创建权限 store（`permission.js`）：根据用户角色动态生成菜单和路由
   - 定义完整菜单结构（工作台、病例管理 7 个子菜单、健康筛查、统计分析、通知公告、用户管理、系统管理）
   - 实现菜单权限过滤逻辑：
     - 超级管理员：显示所有菜单
     - 医院管理员：隐藏系统管理，显示用户管理（本院）
     - 普通医生：隐藏用户管理和系统管理
   - 实现动态路由注册：登录后根据角色动态添加路由
   - 更新路由守卫：集成权限校验逻辑
   - _需求：7.2、7.3_

- [ ] 7. 实现 PC 端登录页面
   - 在 `src/views/login/LoginView.vue` 中实现完整的登录页面：
     - 左侧品牌展示区（系统名称 + 简介 + 背景图/渐变色）
     - 右侧登录表单（用户名 + 密码 + 登录按钮）
     - 「记住用户名」复选框（localStorage 持久化）
     - 「忘记密码?」链接（弹出提示「请联系系统管理员重置密码」）
     - 回车键提交、表单校验、登录中 loading 状态
   - 实现登录成功后的处理流程：存储 Token → 获取用户信息 → 生成动态路由 → 跳转首页
   - 实现强制改密对话框（首次登录/默认密码）
   - 实现改密提醒对话框（超过 6 个月，支持「立即修改」和「稍后再说」）
   - _需求：4.2（前端部分）_

- [ ] 8. 实现 PC 端用户管理页面

     - 医院管理员视图：自动限定本院，隐藏医院筛选和删除按钮
   - 创建用户新增/编辑抽屉组件 `UserForm.vue`：
