# V2版本测试验证方案需求文档

> **实施优先级：Plan 4（最后执行）**
> **前置依赖：Plan 1～3 全部完成（环境就绪、监控就绪、Mock 数据就绪）**

> **精简说明：** 原文档包含 7 个需求（单元测试、集成测试、E2E、CI/CD、性能测试、安全测试、UAT）。经梳理，CI/CD 流水线、安全渗透测试、用户验收测试属于后续阶段工作，当前核心目标是"本地验证 V2 重构代码的正确性"。因此精简为 4 个聚焦当前阶段的需求，后续阶段需求可在本轮验证通过后再规划。

## 引言

随着 V2 版本开发基本完成，为确保重构代码的质量和稳定性，需要制定测试验证方案。本方案聚焦于当前阶段可执行的测试工作：单元测试覆盖、集成测试与数据验证、端到端功能测试、以及基础性能验证。通过这四层测试，逐步验证 V2 版本的功能正确性和稳定性。

---

## 需求

### 需求 1：单元测试覆盖

**用户故事：** 作为质量保证工程师，我希望建立完整的单元测试覆盖，以便验证每个代码模块的功能正确性

#### 验收标准

1. WHEN 运行单元测试套件 THEN 系统 SHALL 达到 80% 以上的整体代码覆盖率
2. IF 存在核心业务逻辑模块 THEN 系统 SHALL 达到 95% 以上的代码覆盖率
3. WHEN 执行单元测试 THEN 系统 SHALL 所有测试用例通过率达到 100%
4. WHEN 新增或修改代码 THEN 系统 SHALL 要求相应的单元测试用例同步更新

---

### 需求 2：集成测试与数据验证

**用户故事：** 作为测试工程师，我希望执行集成测试并验证数据迁移完整性，以便确认各模块协作、数据流和历史数据的正确性

#### 验收标准

1. WHEN 运行集成测试 THEN 系统 SHALL 验证所有 API 接口的连通性和数据一致性
2. IF 存在数据库操作 THEN 系统 SHALL 验证数据读写的一致性和事务完整性
3. WHEN 执行跨模块调用测试 THEN 系统 SHALL 确保模块间数据传递的正确性
4. WHEN 执行数据迁移验证 THEN 系统 SHALL 对比迁移前后数据，确保历史数据的完整性和准确性

---

### 需求 3：端到端测试与异常容错

**用户故事：** 作为产品经理，我希望进行端到端功能测试，以便验证用户核心业务流程的完整性和系统容错能力

#### 验收标准

1. WHEN 执行端到端测试 THEN 系统 SHALL 覆盖所有核心业务流程（患者管理、病例录入、随访记录、数据导出等）
2. WHEN 测试异常流程 THEN 系统 SHALL 验证系统的错误处理和恢复能力
3. WHEN 测试权限隔离 THEN 系统 SHALL 验证不同角色（超级管理员、医院管理员、医生、家长）的数据隔离正确性
4. WHEN 执行数据流测试 THEN 系统 SHALL 确保数据从输入到输出的完整链路正确

---

### 需求 4：基础性能验证

**用户故事：** 作为开发工程师，我希望对核心接口进行基础性能验证，以便确认 V2 重构后的性能不低于 V1 版本

> **范围说明：** 本需求为基础性能验证，非正式的压力测试。主要目的是确认重构后无明显性能退化，借助 Plan 2 已建立的 Grafana 大盘观察指标。

#### 验收标准

1. WHEN 执行核心 API 性能测试 THEN 系统 SHALL 满足以下基础响应时间指标：
   - 患者列表查询 API 响应 < 500ms（含分页）
   - 病例详情查询 API 响应 < 300ms
   - 随访记录查询 API 响应 < 300ms
2. WHEN 模拟 10 个并发用户操作 THEN 系统 SHALL 保持稳定运行，无报错、无超时
3. WHEN 执行性能测试期间 THEN 系统 SHALL 通过 Grafana 大盘观察以下指标无异常：
   - HTTP 错误率 < 1%
   - HikariCP 连接池无等待（pending = 0）
   - JVM 堆内存无持续增长趋势（排除内存泄漏）
4. WHEN 性能测试完成 THEN 系统 SHALL 输出测试报告，包含各接口的平均响应时间、P95 响应时间和错误率
