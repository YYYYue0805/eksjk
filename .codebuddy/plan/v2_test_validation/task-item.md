# 实施计划：V2 版本测试验证方案（Plan 4）

> 本任务清单基于 `v2_test_validation/requirements.md` 需求文档生成。
> 前置依赖：Plan 1～3 全部完成（K8S 环境就绪、监控就绪、Mock 数据就绪）。

---

- [ ] 1. 搭建单元测试基础设施
   - 在后端 `pom.xml` 中确认 `spring-boot-starter-test`、`mockito`、`jacoco-maven-plugin` 依赖
   - 配置 JaCoCo 插件生成覆盖率报告，设置整体覆盖率阈值 80%
   - 创建测试基类（`BaseServiceTest`），统一配置 Mock 环境和测试数据工厂
   - _需求：1.1 ~ 1.4_

- [ ] 2. 编写核心业务模块单元测试
   - 为患者管理 Service 编写单元测试（CRUD 操作、疾病类型筛选、分页查询）
   - 为随访管理 Service 编写单元测试（随访记录 CRUD、MAS 专属随访、生长数据计算）
   - 为认证模块编写单元测试（登录验证、Token 生成、权限校验）
   - 为数据导出模块编写单元测试（EasyExcel 导出逻辑）
   - 确保核心业务逻辑模块覆盖率 ≥ 95%
   - _需求：1.1 ~ 1.2_

- [ ] 3. 编写集成测试（API 接口 + 数据库）
   - 使用 `@SpringBootTest` + `TestRestTemplate` 编写 API 集成测试
   - 测试所有核心 API 接口的连通性和数据一致性（患者 CRUD、病例详情、随访记录）
   - 验证数据库事务完整性（并发写入、回滚场景）
   - 验证跨模块数据传递正确性（患者 → 病例 → 随访的关联查询）
   - _需求：2.1 ~ 2.4_

- [ ] 4. 编写端到端测试用例（核心业务流程 + 权限隔离）
   - 编写核心业务流程 E2E 测试：登录 → 创建患者 → 录入病例 → 添加随访 → 查询列表 → 导出数据
   - 编写权限隔离测试：分别以 super_admin、hospital_admin、doctor、parent 角色登录，验证数据隔离
   - 编写异常容错测试：无效参数、越权访问、并发冲突等异常场景的错误处理
   - _需求：3.1 ~ 3.4_

- [ ] 5. 编写基础性能验证脚本并生成测试报告
   - 编写性能测试脚本（可使用 JMeter 或 k6），覆盖患者列表查询、病例详情查询、随访记录查询
   - 配置 10 并发用户场景，验证响应时间指标（列表 < 500ms、详情 < 300ms）
   - 测试期间通过 Grafana 大盘观察 HTTP 错误率、HikariCP 连接池、JVM 堆内存趋势
   - 生成测试报告：各接口平均响应时间、P95 响应时间、错误率
   - _需求：4.1 ~ 4.4_
